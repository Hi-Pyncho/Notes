### 1. **`ss`** (современная и быстрая утилита)
```bash
ss -tulnp
```
- `-t` — TCP
- `-u` — UDP
- `-l` — только слушающие (listening) сокеты
- `-n` — не резолвить имена (показывать порты как числа)
- `-p` — показать PID и имя процесса

Пример вывода:
```
Netid  State   Recv-Q Send-Q Local Address:Port  Peer Address:Port
tcp    LISTEN  0      128    127.0.0.1:5000       0.0.0.0:*        users:(("dotnet",pid=1234,fd=42))
```

### 2. **`lsof`** (list open files — сокеты тоже считаются «файлами»)
```bash
sudo lsof -i -P -n | grep LISTEN
```
- `-i` — показать сетевые соединения
- `-P` — не преобразовывать номера портов в имена
- `-n` — не резолвить IP-адреса в имена

Или конкретно для dotnet:
```bash
lsof -i -P -n | grep dotnet
```

### 3. **`netstat`** (устаревшая, но всё ещё часто доступна)
```bash
netstat -tulnp
```
То же, что и `ss`, но медленнее и в новых дистрибутивах может отсутствовать.

---

Если вы запустили .NET-приложение локально и не знаете порт — скорее всего, это **5000** (HTTP) и/или **5001** (HTTPS), так как это стандартные порты Kestrel-сервера в .NET по умолчанию.

Но лучше всего проверить командой:
```bash
ss -tulnp | grep dotnet
```

Если `ss` не установлен (редко), используйте `lsof` или `netstat`.

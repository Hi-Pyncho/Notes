## Общая картина: как устроена память в программе на C

Когда запускается программа на C, операционная система выделяет **виртуальное адресное пространство**, которое делится на несколько **регионов**:

```
+---------------------+
|      Stack          | ← растёт вниз
| (локальные переменные, вызовы функций)
|                     |
|        ...          |
|                     |
|      Heap           | ← растёт вверх
| (выделенная вручную память: malloc)
|                     |
|    Uninitialized    |
|    Data (.bss)      |
|    Initialized      |
|    Data (.data)     |
|    Code (Text)      | ← код программы
+---------------------+
↓
Адреса растут
```

---

## 1. Stack (стек)

### 📌 Что хранится:
- Локальные переменные функций
- Параметры функций
- Возвратные адреса (чтобы знать, куда вернуться после `return`)
- Информация о вызовах функций (stack frame / кадр стека)

### ✅ Особенности:
| Характеристика | Описание |
|----------------|--------|
| **Управление** | Автоматическое (компилятор) |
| **Выделение** | При входе в функцию |
| **Освобождение** | При выходе из функции (`return`) |
| **Скорость** | Очень быстрое выделение/освобождение |
| **Размер** | Ограничен (обычно 1–8 МБ, зависит от ОС) |
| **Доступ** | Прямой, через имя переменной |

### Пример:
  ```c
void func() {
  int x = 10;        // x — в стеке
  double arr[100];   // массив — тоже в стеке
} // x и arr уничтожаются автоматически
```

### ⚠️ Ограничения:
- Нельзя возвращать указатель на локальную переменную:
```c
int* bad() {
  int x = 5;
  return &x; // ❌ Указатель станет висячим!
}
```
- Глубокая рекурсия может вызвать **переполнение стека (stack overflow)**.

## 2. Heap (куча)

### 📌 Что хранится:
- Память, выделенная **вручную** с помощью `malloc`, `calloc`, `realloc`
- Динамические структуры: массивы, деревья, списки и т.д.

### ✅ Особенности:
| Характеристика | Описание |
|----------------|--------|
| **Управление** | Ручное (программист) |
| **Выделение** | `malloc()`, `calloc()`, `realloc()` |
| **Освобождение** | `free()` |
| **Скорость** | Медленнее, чем стек (вызов системы) |
| **Размер** | Ограничен только памятью системы и ОС |
| **Доступ** | Через указатели |

### Пример:
```c
int* create_array(int n) {
  int* arr = malloc(n * sizeof(int)); // выделение в куче
  if (arr == NULL) {
    // обработка ошибки
  }
  return arr; // можно возвращать — память не исчезнет
}

int main() {
  int* data = create_array(1000);
  // ... используем
  free(data); // ⚠️ Обязательно освободить!
  return 0;
}
```

### ⚠️ Опасности:
- **Утечки памяти (memory leak)**: если забыть `free()`
- **Висячие указатели (dangling pointer)**: после `free()` указатель становится недействительным
- **Дважды `free()`**: UB (неопределенное поведение)

## Сравнение: Stack vs Heap

| Критерий | Stack | Heap |
|---------|-------|------|
| **Управление памятью** | Автоматическое | Ручное |
| **Скорость** | Очень высокая | Ниже (системные вызовы) |
| **Размер** | Маленький (МБ) | Большой (ГБ) |
| **Жизненный цикл** | До выхода из функции | До `free()` |
| **Выделение** | `int x;` | `malloc()` |
| **Освобождение** | Автоматически | `free()` |
| **Фрагментация** | Нет | Может быть (особенно при частых `malloc/free`) |
| **Потокобезопасность** | Каждый поток — свой стек | Куча общая, нужна синхронизация |
| **Использование** | Локальные переменные, небольшие данные | Большие данные, динамические структуры |

  ---

## Когда что использовать?

### ✅ Используй **stack**, если:
- Переменная нужна только в одной функции
- Размер известен на этапе компиляции
- Объект небольшой (не массив из миллиона элементов)
- Хочешь автоматическое освобождение

### ✅ Используй **heap**, если:
- Размер неизвестен на этапе компиляции
- Нужно передать данные из функции (возвращая указатель)
- Нужен большой массив или структура
- Ты создаешь динамические структуры: linked list, tree, graph

## Пример: stack vs heap

  ```c
#include <stdio.h>
#include <stdlib.h>

  void stack_example() {
    int arr[1000]; // 4000 байт — в стеке
    arr[0] = 42;
    // автоматически очистится
  }

void heap_example() {
  int* arr = malloc(1000 * sizeof(int)); // в куче
  if (arr) {
    arr[0] = 42;
    // ... используем
    free(arr); // ❗обязательно освободить
  }
}
```

> 💡 Если сделать `int arr[1000000];` в стеке — может быть **stack overflow**.

---

## Распространённые ошибки

| Ошибка | Пример |
|-------|--------|
| **Утечка памяти** | `malloc()` без `free()` |
| **Висячий указатель** | `free(p); printf("%d", *p);` |
| **Двойной `free`** | `free(p); free(p);` → UB |
| **Выход за пределы массива в куче** | `arr[1000] = 5;` (если выделено 100) |
| **Использование стека после выхода** | `return &local_var;` |

## Подсказка: как проверить размер стека?

На Linux можно посмотреть:
```bash
ulimit -s   # покажет размер стека в килобайтах
```

Изменить (временно):
```bash
  ulimit -s 16384  # 16 МБ
 ```

## Вывод

| — | Stack | Heap |
|----|--------|--------|
| **Кто управляет** | Компилятор | Программист |
| **Когда использовать** | Локальные, маленькие, временные данные | Большие, динамические, долгоживущие данные |
| **Плюсы** | Быстро, безопасно, автоматически | Гибко, масштабируемо |
| **Минусы** | Ограничен, переполнение | Риск утечек, ошибок, медленнее |

> 💡 **Правило**: по умолчанию используй **stack**. Переходи на **heap**, только когда **нужно**.

## Что такое `malloc` и `free`?

Они позволяют **выделять и освобождать память в куче (heap)** во время выполнения программы.

- `malloc` — **memory allocate** → выделяет блок памяти
- `free` — освобождает ранее выделенный блок

Используются для:
- Массивов неизвестного размера
- Динамических структур данных (списки, деревья, графы)
- Когда нужно, чтобы память "жила" дольше, чем функция

---

## Подключение

```c
#include <stdlib.h>  // нужен для malloc и free
```

---

## `malloc(size_t size)`

### 💡 Назначение:
Выделяет **непрерывный блок памяти указанного размера в байтах**.

### 📌 Синтаксис:
```c
void* malloc(size_t size);
```

- Возвращает **указатель на начало блока**
- Тип возврата — `void*` → можно привести к любому другому указателю
- Если память выделить не удалось — возвращает `NULL`

### ✅ Пример:
```c
int* arr = malloc(10 * sizeof(int));
if (arr == NULL) {
  printf("Ошибка выделения памяти!\n");
  return -1;
}
```

Теперь `arr` — массив из 10 `int`, как `int arr[10]`, но в **куче**, а не в стеке.

---

## `free(void* ptr)`

### 💡 Назначение:
Освобождает ранее выделенный блок памяти.

### 📌 Синтаксис:
```c
void free(void* ptr);
```

- Принимает указатель, полученный от `malloc`, `calloc` или `realloc`
- **Не делает указатель `NULL` автоматически!**
- Можно вызывать только на:
  - Указатели от `malloc/calloc/realloc`
  - Или `NULL` (безопасно)
- Нельзя вызывать дважды на один и тот же указатель

### ✅ Пример:
```c
free(arr);     // освобождаем память
arr = NULL;    // хорошая практика — обнулить указатель
```

---

## Как это работает "под капотом"?

### 1. Память берётся из **кучи (heap)**

- Куча — это область памяти, выделенная процессу ОС
- Управляет ею **аллокатор памяти** (в Linux — `glibc`, использует `ptmalloc`)

### 2. При `malloc`:
- Аллокатор ищет **свободный блок нужного размера**
- Использует **списки свободных блоков (free lists)**, разделённые по размеру
- Помечает блок как **занятый**
- Возвращает указатель на пользовательскую часть

### 3. При `free(ptr)`:
- Аллокатор **помечает блок как свободный**
- Добавляет его в список свободных
- Может **объединить (coalesce)** с соседними свободными блоками
- **Но не перемещает блоки** → фрагментация возможна

---

## Что хранится в памяти?

Аллокатор добавляет **служебную информацию (заголовок)** перед выделенным блоком:

```
+----------------+-----------------------------+
| Заголовок      | Пользовательская память     |
| (size, flags)  | (то, что возвращает malloc) |
+----------------+-----------------------------+
                 ↑
           возвращается как void*
```

Эта информация используется при `free`, чтобы знать:
- Размер блока
- Занят он или свободен
- Соседние блоки

---

## Другие функции: `calloc` и `realloc`

### 1. `calloc(size_t num, size_t size)`
Выделяет память для массива и **обнуляет её**.

```c
int* arr = calloc(10, sizeof(int)); // как malloc + memset(0)
```

Эквивалентно:
```c
int* arr = malloc(10 * sizeof(int));
memset(arr, 0, 10 * sizeof(int));
```

### 2. `realloc(void* ptr, size_t new_size)`
Изменяет размер ранее выделенного блока.

```c
arr = realloc(arr, 20 * sizeof(int)); // увеличиваем массив
```

- Может **переместить** блок в другое место
- Возвращает новый указатель (или `NULL`, если не хватило памяти)
- Старые данные копируются

---

## Важные правила и ошибки

| Ошибка | Последствия |
|--------|------------|
| ❌ Забыть проверить `malloc` на `NULL` | Программа упадёт при `arr[0] = 5` |
| ❌ Не вызвать `free` | **Утечка памяти (memory leak)** |
| ❌ Вызвать `free` дважды | **Двойное освобождение** → UB, может сломать аллокатор |
| ❌ Читать после `free` | **Висячий указатель** → UB, мусор или падение |
| ❌ Переписать за границей массива | Повреждение заголовков → `malloc/free` сломается |
| ❌ Вызвать `free` на стековом указателе | `free(&x)` → UB |

---

## Пример: динамический массив

```c
#include <stdio.h>
#include <stdlib.h>

int main() {
  int n = 5;
  int* arr = malloc(n * sizeof(int));

  if (!arr) {
    printf("Ошибка выделения\n");
    return 1;
  }

  for (int i = 0; i < n; i++) {
    arr[i] = i * i;
  }

  for (int i = 0; i < n; i++) {
    printf("%d ", arr[i]);
  }
  printf("\n");

  free(arr);    // обязательно!
  arr = NULL;   // хорошая практика

  return 0;
}
```

---

## Когда использовать `malloc/free`?

✅ Используй, если:
- Размер массива неизвестен на этапе компиляции
- Нужно, чтобы память жила после выхода из функции
- Работаешь с динамическими структурами: списки, деревья и т.д.

❌ Не используй, если:
- Можно использовать стек: `int arr[100];`
- Нужен временный буфер малого размера

---

## Где хранится память?

- `malloc` → **куча (heap)** → растёт вверх
- Локальные переменные → **стек (stack)** → растёт вниз
- Глобальные переменные → **.data / .bss**
- Код программы → **.text**

---

## Вывод

| Функция | Назначение | Важно |
|--------|-----------|------|
| `malloc` | Выделяет память | Проверяй на `NULL` |
| `calloc` | Выделяет и обнуляет | Удобно для массивов |
| `realloc` | Изменяет размер | Может переместить блок |
| `free` | Освобождает | Только на `malloc`, не дважды |

---

💡 **Правила большого пальца:**
1. Всегда проверяй `malloc` на `NULL`
2. Всегда вызывай `free` для каждого `malloc`
3. Никогда не используй память после `free`
4. Обнуляй указатель после `free` (по желанию, но безопасно)
5. Не забывай `#include <stdlib.h>`

## Где хранится метаинформация о блоках?

Когда ты вызываешь:
```c
void* ptr = malloc(100);
```

Аллокатор:
1. Находит подходящий свободный блок
2. **Резервирует немного дополнительной памяти** для **заголовка (header)**
3. В этом заголовке хранит:
   - Размер блока
   - Флаг: свободен или занят
   - Указатели на следующие/предыдущие блоки (если используется список)

📌 Эта информация **не видна программисту** — она скрыта **до или после** выделенного блока.

---

## 🔹 Пример: устройство блока памяти

```
          ↓ ptr возвращается пользователю
+--------+---------------------+
| Header |     Пользовательская память (100 байт) |
+--------+---------------------+
 ↑
 Скрытый заголовок (например, 8–16 байт)
```

### Что в заголовке?
| Поле | Описание |
|------|---------|
| `size` | Размер блока (включая заголовок) |
| `free` | Флаг: 1 — свободен, 0 — занят |
| `prev`, `next` | Указатели для списка свободных блоков (если блок свободен) |

---

## Где именно хранится заголовок?

Обычно **непосредственно перед** выделенной пользователю памятью:

```c
// Псевдокод аллокатора
struct block_header {
  size_t size;      // размер блока
  int free;          // свободен?
  struct block_header* next;
  struct block_header* prev;
};

// При malloc:
// 1. Найти подходящий блок
// 2. Записать header перед памятью
// 3. Вернуть указатель на начало данных (после header)
```

Когда ты вызываешь `free(ptr)`:
- Аллокатор **отступает назад от `ptr`** на размер заголовка
- Читает `size`, `free`, и т.д.
- Помечает блок как свободный
- Добавляет в список свободных

---

## Как устроены списки свободных блоков?

Аллокатор ведёт **списки (или массивы списков) свободных блоков** по размерам:

### Пример: **разделённые свободные списки (segregated free lists)**

```c
free_list[0] → блоки 8–16 байт
free_list[1] → блоки 17–32 байт
...
free_list[N] → большие блоки
```

При `malloc(20)`:
- Ищет в `free_list[1]`
- Если нет — берёт из большего списка или запрашивает у ОС

---

## Где хранятся сами списки?

Списки свободных блоков хранятся **в куче (heap)** или **в глобальных переменных самого аллокатора**.

Например, в `glibc` (аллокатор `ptmalloc`, основанный на `dlmalloc`):
- Есть глобальная структура `malloc_state`
- В ней — массивы указателей на свободные блоки
- Эта структура хранится где-то в памяти процесса

---

## Пример: простой аллокатор (упрощённо)

```c
struct block {
  size_t size;
  int free;
  struct block* next;
};

struct block* free_list = NULL;

void* malloc(size_t size) {
  // Ищем в free_list блок нужного размера
  // Если нашли — удаляем из списка, помечаем как занятый
  // Возвращаем указатель на данные (после struct block)
}

void free(void* ptr) {
  // ptr - sizeof(struct block) → получаем заголовок
  // Помечаем как free
  // Добавляем в free_list
}
```

## Что такое "бининг" (binning)?

Многие аллокаторы (включая `glibc`) используют **бины (bins)** — это корзины для свободных блоков по размеру:

| Тип бина | Назначение |
|---------|-----------|
| **Fast bins** | Маленькие блоки, LIFO, без слияния |
| **Unsorted bin** | Недавно освобождённые блоки |
| **Small bins** | Блоки малого фиксированного размера (до ~512 байт) |
| **Large bins** | Большие блоки разного размера |

Это позволяет быстро находить подходящий блок.

---

## А что с большими блоками?

Для **очень больших блоков** (например, >128 КБ) аллокатор может использовать системный вызов `mmap`:

```c
ptr = mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
```

- Такие блоки выделяются **отдельно от основной кучи**
- При `free` они могут быть сразу возвращены ОС через `munmap`

Это помогает избежать фрагментации в основной куче.

---

## Что хранится в заголовке: пример

```c
struct malloc_chunk {
  size_t      prev_size;  // размер предыдущего блока (если свободен)
  size_t      size;       // размер этого блока + флаги в младших битах

  struct malloc_chunk* fd; // forward pointer (в списке свободных)
  struct malloc_chunk* bk; // backward pointer
  // ... и другие поля
};
```

📌 Интересно: **младшие биты `size` используются как флаги**:
- `size & 1` → занят ли блок
- `size & 2` → предыдущий блок занят?
- Так экономится память — не нужно отдельных полей

| **Где хранится информация о блоках?** | В **заголовках (headers)** перед или после данных |

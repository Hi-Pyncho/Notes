## Что такое «быстрые типы»?

**«Быстрые типы»** — это типы из заголовка `<stdint.h>`, которые обозначаются как `int_fastN_t` или `uint_fastN_t`. Они выбираются так, чтобы **обеспечить максимальную производительность** при работе с целыми числами **не меньше N бит**.

> 💡 Цель: **быстрая арифметика**, а не минимальный размер.

---

### Примеры

```c
#include <stdint.h>

int_fast8_t  a;   // "быстрый" тип ≥8 бит
int_fast16_t b;   // "быстрый" тип ≥16 бит
uint_fast32_t c;  // "быстрый" беззнаковый тип ≥32 бит
```

---

## Как это работает?

Процессоры работают **быстрее** с теми типами данных, которые соответствуют их **нативной разрядности**.

Например:
- На 32-битной системе **нативный тип** — 32 бита (`int`)
- На 64-битной — 64 бита (`long` или `long long`)

Поэтому:
- Даже если тебе нужно хранить число от 0 до 100 (и хватило бы 8 бит), **работа с `int` (32 бита)** будет **быстрее**, чем с `int8_t`, потому что:
  - Процессору не нужно маскировать биты
  - Нет дополнительных операций приведения
  - Лучше работает с регистрами

Компилятор может использовать **целый 32-битный регистр**, даже если ты используешь 8-битную переменную — и тогда `int_fast8_t` окажется равным `int`.

---

### Пример: `int_fast8_t` не обязательно 8 бит!

```c
#include <stdio.h>
#include <stdint.h>

int main() {
  printf("Размер int_fast8_t: %zu байта\n", sizeof(int_fast8_t));
  return 0;
}
```

На большинстве современных систем (x86-64) вывод будет:
```
Размер int_fast8_t: 4 байта
```

Потому что **самый быстрый тип ≥8 бит** — это `int` (32 бита).  
Он "жертвует" памятью, но выигрывает в скорости.

---

## Сравнение: `int_least8_t` vs `int_fast8_t`

| Тип | Цель | Типичный размер |
|------|------|-----------------|
| `int_least8_t` | **Минимально возможный** тип ≥8 бит | 1 байт |
| `int_fast8_t`  | **Самый быстрый** тип ≥8 бит | 4 байта (на 32/64-битных системах) |

Используй:
- `int_least8_t` — если **важна экономия памяти** (например, массив из миллиона элементов)
- `int_fast8_t` — если **важна скорость** (например, счётчик в цикле)

---

## Где применяются «быстрые типы»?

1. **Счётчики в циклах**
   ```c
   for (int_fast32_t i = 0; i < 1000000; i++) { ... }
   ```
   → Быстрее, чем `int8_t` или `int16_t`, даже если значения маленькие.

2. **Временные переменные в математике**
3. **Внутренние переменные в критичных по скорости участках кода**

---

## Почему не всегда использовать `int_fast`?

Потому что:
- Они **могут занимать больше памяти**
- В **массивах** или **структурах** это может быть неэффективно

Пример:
```c
struct Pixel {
  uint8_t r, g, b;        // 3 байта
  // vs
  uint_fast8_t r, g, b;   // 12 или 24 байта! — слишком много
};
```

Здесь `uint8_t` лучше: мы знаем, что цвет — от 0 до 255, и хотим экономить память.

---

## Вывод

| Тип | Когда использовать |
|------|---------------------|
| `int_leastN_t` | Когда **важно не превышать размер**, но нужно минимум N бит |
| `int_fastN_t`  | Когда **важна скорость**, а память — не критична |

> 💡 Эти типы — часть стандарта C99 и помогают писать **и эффективный, и переносимый код**.

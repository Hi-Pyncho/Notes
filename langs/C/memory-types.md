## Основные сегменты памяти в C-программе

Когда программа на C компилируется и запускается, её память делится на несколько **сегментов (или секций)**. Каждая из них предназначена для хранения определённого типа данных.

Вот основные:

| Сегмент | Назначение | Доступ |
|--------|-----------|--------|
| **`.text`** | Машинный код программы (функции, инструкции) | Только чтение |
| **`.rodata`** | Константные данные (например, строковые литералы) | Только чтение |
| **`.data`** | Инициализированные глобальные и статические переменные | Чтение и запись |
| **`.bss`** | Неинициализированные глобальные/статические переменные | Чтение и запись |
| **Стек (stack)** | Локальные переменные, параметры функций, адреса возврата | Чтение и запись |
| **Куча (heap)** | Динамически выделяемая память (`malloc`, `calloc`, `realloc`) | Чтение и запись |

---

### 1. `.text` — код программы

- Содержит **машинные инструкции** (скомпилированный код функций).
- Пример: тело функции `main`, `printf`, твои функции.
- Обычно **нельзя писать** в эту область (защита от самомодифицирующегося кода).
- Читается процессором при выполнении.

```c
void hello() {
  printf("Hello\n");  // Этот код попадёт в .text
}
```

---

### 2. `.rodata` — **Read-Only Data**

#### Что хранится:
- **Строковые литералы**: `"hello"`, `"error: file not found"`
- **Константы с модификатором `const`**, если они не в стеке:
  ```c
  const int max = 100; // Может быть в .rodata, если глобальная
  ```
- Массивы или структуры, объявленные как `const`.

#### Пример:
```c
char *name = "Alice";
```
- `"Alice"` — строковый литерал → хранится в `.rodata`.
- `name` — указатель, хранится в стеке или `.data`, но **указывает на `.rodata`**.

#### Особенности:
- Память **только для чтения**.
- Попытка записи → **ошибка сегментации (segmentation fault)**.
  ```c
  name[0] = 'X'; // ❌ UB, может упасть с SIGSEGV
  ```
- Выделяется **на этапе компиляции**.
- Размер ограничен только возможностями компилятора и ОС.

#### Зачем нужен?
- Защита от случайного изменения строк.
- Оптимизация: строковые литералы могут **сворачиваться** (например, два `"hello"` → один экземпляр).
- Эффективное хранение констант.

---

### 3. `.data` — инициализированные глобальные/статические переменные

#### Что хранится:
- Глобальные переменные, которым задано начальное значение.
- Статические переменные (в функциях и файлах).

```c
int global_var = 42;           // → .data
static int counter = 0;        // → .data
char greeting[] = "Hi!";       // → .data (массив, а не указатель!)
```

> ⚠️ Обрати внимание:
> ```c
> char *p = "Hi";     // p — в .data или стеке, "Hi" — в .rodata
> char arr[] = "Hi";  // arr — в .data, и строка скопирована сюда
> ```

---

### 4. `.bss` — Block Started by Symbol

#### Что хранится:
- Глобальные и статические переменные, **не инициализированные явно**.
- Инициализируются в ноль при запуске.

```c
int buffer[1000];           // → .bss (не инициализирован)
static double values[256];  // → .bss
```

#### Особенности:
- В исполняемом файле **не занимает места** (только метаданные: "здесь будет 1000 int").
- При запуске ОС выделяет и обнуляет память.
- Экономит размер бинарника.

---

### 5. **Стек (stack)**

#### Что хранится:
- Локальные переменные функций.
- Параметры функций.
- Адреса возврата (чтобы знать, куда вернуться после `return`).
- Временные данные.

```c
void func(int x) {
  int a = 10;           // → стек
  char name[20];        // → стек
  double result;        // → стек
}
```

#### Особенности:
- Работает по принципу **LIFO** (последним пришёл — первым ушёл).
- Автоматическое выделение и освобождение (`push` / `pop`).
- Ограничен по размеру (обычно 1–8 МБ, зависит от ОС).
- Переполнение стека → `stack overflow`.

---

### 6. **Куча (heap)**

#### Что хранится:
- Память, выделенная **динамически** с помощью:
  - `malloc()`
  - `calloc()`
  - `realloc()`

```c
int *arr = malloc(100 * sizeof(int));  // → heap
char *str = strdup("Hello");           // → heap
```

#### Особенности:
- Управляется **вручную** программистом.
- Нет автоматического освобождения — нужно вызывать `free()`.
- Перераспределение: можно `realloc`.
- Меньше по скорости, чем стек, но больше по размеру (ограничена памятью системы).
- Утечки памяти (`memory leaks`) — частая ошибка.

## 🧩 Визуализация памяти (упрощённо)

```
Высший адрес памяти
┌──────────────────────┐
│         Stack        │ ← растёт вниз
├──────────────────────┤
│         Heap         │ ← растёт вверх
├──────────────────────┤
│         .bss         │
├──────────────────────┤
│         .data        │
├──────────────────────┤
│        .rodata       │
├──────────────────────┤
│         .text        │
└──────────────────────┘
Низший адрес памяти
```

> ⚠️ На практике порядок может отличаться (например, `.rodata` рядом с `.text`), но общая идея:  
> - `.text`, `.rodata`, `.data`, `.bss` — "статические" секции.  
> - Стек и куча — динамические, растут навстречу друг другу.

---

## 🔍 Пример: где что лежит?

```c
#include <stdio.h>
#include <stdlib.h>

const char *global_str = "I'm in .rodata";  // global_str → .data, строка → .rodata
int initialized = 42;                       // → .data
int uninitialized;                          // → .bss

int main() {
  char *heap_str = malloc(20);            // heap_str → stack, память → heap
  strcpy(heap_str, "Heap data");

  char *ro_str = "Also in .rodata";       // ro_str → stack, строка → .rodata

  char local_str[] = "On the stack";      // весь массив → stack

  static int counter = 0;                 // → .data (статическая переменная)

  printf("%p: %s\n", (void*)global_str, global_str);
  printf("%p: %s\n", (void*)ro_str, ro_str);
  printf("%p: %s\n", (void*)local_str, local_str);

  free(heap_str);
  return 0;
}
```

---

## 💡 Полезные советы

1. **Строковые литералы — нельзя менять** → ошибка сегментации.
2. Если нужно изменять строку — копируй в стек (`char buf[] = "..."`) или в кучу (`malloc + strcpy`).
3. Глобальные/статические массивы с инициализацией → `.data`.
4. Неинициализированные глобальные массивы → `.bss` (экономит место в бинарнике).
5. Большие данные — не клади в стек (риск `stack overflow`), лучше в кучу.
6. Всегда `free` память из `malloc`.

---

## Как посмотреть, где что лежит?

Можно использовать `gdb` или просто вывести адреса:

```c
printf("rodata: %p\n", (void*)"hello");
printf("data:    %p\n", (void*)&initialized);
printf("bss:     %p\n", (void*)&uninitialized);
printf("stack:   %p\n", (void*)&local_str);
printf("heap:    %p\n", (void*)heap_str);
```

Обычно:
- `.rodata`, `.text`, `.data`, `.bss` — близкие адреса (ниже).
- Стек — где-то посередине.
- Куча — может быть в другом месте.

---

## ✅ Вывод

- `.rodata` — это **сегмент только для чтения**, где хранятся **строковые литералы и константы**.
- Он **не является стеком или кучей** — это часть **статической памяти** программы.
- При присваивании `char *s = "long text"`:
  - Сама строка — в `.rodata`.
  - Указатель `s` — в стеке (или `.data`).
  - Память в heap **не выделяется автоматически**.
- Чтобы изменять строку — нужно **скопировать** её в стек или кучу.

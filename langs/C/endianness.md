**Endianness** (порядок байтов) — это один из фундаментальных концептов в системном программировании, который определяет, **как многобайтовые значения (например, `int`, `float`) хранятся в памяти**.

Понимание endianness критически важно при:
- Работе с сетевыми протоколами
- Чтении/записи бинарных файлов
- Встраиваемых системах (embedded)
- Декодировании данных (например, изображений, аудио)

---

## Что такое Endianness?

**Endianness** — это **порядок байтов** в многобайтовом значении (например, 32-битное число `0x12345678`).

Существует два основных порядка:

| Тип | Описание |
|-----|---------|
| **Little-endian** | Младший байт хранится по младшему адресу |
| **Big-endian**   | Старший байт хранится по младшему адресу |

---

## Пример: число `0x12345678`

Представим 32-битное число: `0x12345678`  
(в двоичном виде: `00010010 00110100 01010110 01111000`)

### 📌 1. **Big-endian** («старший вперед»)

Байты хранятся **в прямом порядке**:

```
Адрес:    ↑ 0x1000    0x1001    0x1002    0x1003
          +---------+---------+---------+---------+
          | 0x12    | 0x34    | 0x56    | 0x78    |
          +---------+---------+---------+---------+
```

👉 Старший байт `0x12` — по младшему адресу.

🔹 Аналогия: как мы читаем число — слева направо: *один-два-три-четыре...*

---

### 📌 2. **Little-endian** («младший вперед»)

Байты хранятся **в обратном порядке**:

```
Адрес:    ↑ 0x1000    0x1001    0x1002    0x1003
          +---------+---------+---------+---------+
          | 0x78    | 0x56    | 0x34    | 0x12    |
          +---------+---------+---------+---------+
```

Младший байт `0x78` — по младшему адресу.

Аналогия: как будто записали число задом наперёд.

---

## Где какой порядок используется?

| Архитектура | Endianness | Где используется |
|------------|------------|------------------|
| **x86, x86-64** | Little-endian | ПК, серверы, ноутбуки |
| **ARM** | Поддерживает оба (bi-endian), но чаще **little-endian** | Мобильные устройства, Raspberry Pi |
| **PowerPC, SPARC, MIPS** | Часто **big-endian** | Старые Mac, сетевые устройства |
| **Network (TCP/IP)** | **Big-endian** | Все сетевые протоколы используют **network byte order** |

---

## Почему это важно?

### ❌ Проблема: обмен данными между системами

Если:
- Машина A (little-endian) записывает `0x12345678` в файл
- Машина B (big-endian) читает его "как есть"

→ Машина B прочитает **другое число**: `0x78563412` → **ошибка!**

## Пример кода: как проверить endianness

```c
#include <stdio.h>

int is_little_endian() {
  int num = 1;
  return *(char*)&num == 1;
}

int main() {
  if (is_little_endian()) {
    printf("Система: little-endian\n");
  } else {
    printf("Система: big-endian\n");
  }
  return 0;
}
```

📌 Как работает:
- `int num = 1` → в памяти: `0x00000001`
- Приводим адрес к `char*` — читаем **первый байт**
- Если он равен `1` → little-endian
- Если `0` → big-endian

## Сетевой порядок байтов (Network Byte Order)

Все сетевые протоколы (IP, TCP, UDP) используют **big-endian** порядок.

Для преобразования есть специальные функции:

```c
#include <arpa/inet.h>  // Linux/BSD
// или <winsock2.h>    // Windows

uint32_t host_to_network = htonl(0x12345678);  // host → network (32-bit)
uint16_t host_to_network_short = htons(0xABCD); // 16-bit

uint32_t network_to_host = ntohl(packet_value);  // network → host
uint16_t network_to_host_short = ntohs(port);
```

📌 Правило:
- При отправке: `htonl`, `htons`
- При приёме: `ntohl`, `ntohs`

> Эти функции **делают ничего** на big-endian машинах, но **переставляют байты** на little-endian.

---

## Как выглядит float в памяти?

Даже числа с плавающей точкой хранятся в зависимости от endianness.

Например, `float x = 3.14f;` — 4 байта.  
Порядок их в памяти зависит от архитектуры.

💡 Но формат **IEEE 754** одинаков — только порядок байтов может меняться.

---

## Можешь ли ты "почувствовать" endianness в обычном C-коде?

❌ **Нет**, если работаешь с обычными переменными:

```c
int x = 0x12345678;
printf("%x\n", x); // Всегда выведет 12345678
```

Компилятор и процессор **автоматически обрабатывают endianness** при доступе к переменным.

✅ **Да**, если смотришь на память через указатели:

```c
int x = 0x12345678;
unsigned char* bytes = (unsigned char*)&x;

printf("Byte 0: %02x\n", bytes[0]); // Может быть 78 или 12 — зависит от endianness!
printf("Byte 1: %02x\n", bytes[1]);
printf("Byte 2: %02x\n", bytes[2]);
printf("Byte 3: %02x\n", bytes[3]);
```

| Характеристика | Little-endian | Big-endian |
|----------------|---------------|------------|
| Младший байт по младшему адресу | ✅ Да | ❌ Нет |
| Старший байт по младшему адресу | ❌ Нет | ✅ Да |
| Используется в x86/x64 | ✅ | ❌ |
| Используется в сетях | ❌ | ✅ (network byte order) |
| Пример: `0x12345678` | `78 56 34 12` | `12 34 56 78` |

## Избегайте глобальных переменных
Рекомендация: Используйте 'use strict', чтобы избежать случайного создания глобальных переменных.

```js
// ❌ Плохо
function processData(data) {
  globalData = data; // случайно создали глобальную переменную
}

// ✅ Хорошо
function processData(data) {
  const localData = data; // локальная переменная
  // ... обработка
}
```

## Управление замыканиями

```js
// ❌ Плохо: замыкание удерживает большой объект
function createHandler(bigData) {
  return function() {
    console.log(bigData.length); // bigData не будет удалён, пока handler жив
  };
}

// ✅ Хорошо: передавайте только нужное
function createHandler(dataLength) {
  return function() {
    console.log(dataLength);
  };
}
```

## Обнулять ссылки явно и ссылки на DOM элементы

```js
let bigArray = new Array(1000000).fill('data');

// После использования:
bigArray = null; // помогает GC
```
```js
// ❌ Плохо
const elem = document.getElementById('temp');
// ... позже elem удалён из DOM, но ссылка висит в памяти

// ✅ Хорошо
elem.remove();
elem = null; // явно удаляем ссылку
```

## WeakMap и WeakSet для кэширования

```js
// ✅ Безопасное кэширование
const cache = new WeakMap();

function process(obj) {
  if (!cache.has(obj)) {
    cache.set(obj, expensiveCalculation(obj));
  }
  return cache.get(obj);
}
// Когда obj удаляется — запись в WeakMap тоже исчезает
```

## Деструктаризация, не хранить лишнего

```js
// ❌ Храните только нужное
function handleUser(user) {
  this.user = user; // хранит весь объект
}

// ✅ Храните только необходимые поля
function handleUser({ id, name }) {
  this.userId = id;
  this.userName = name;
}
```

## Стрктуры данных
- Используйте Map вместо объектов, если ключи динамические — Map эффективнее по памяти и GC.
- Избегайте глубоко вложенных объектов без необходимости.
- Используйте Object.freeze() для констант — иногда помогает оптимизациям.

## Общие советы
- избегать кэши без TTL или ограничения размера
- избегать накопление данных в замыканиях/массивах без очистки
- избегать частого создания объектов в циклах — выносите создание наружу.
- использовать Typed Arrays (Uint8Array, Float32Array) для бинарных данных — эффективнее по памяти и скорости.

## Поиск утечек через heap snapshot
- Выполните действие (открыть компонент, загрузить данные).
- Сделайте Heap Snapshot.
- Выполните обратное действие (закрыть, очистить).
- Принудительно вызовите GC (в DevTools есть кнопка 🗑️).
- Сделайте второй Heap Snapshot.
- Сравните — если объекты остались — утечка.

> 🔍 Ищите: detached DOM nodes, closures, event listeners, retained objects. 

## Горячие точки
В рендере или обработчиках событий (например, mousemove, scroll) избегайте:
- Создания новых объектов ({}), массивов ([])
- Замыканий в циклах
- Частых мутаций сложных структур

Вместо этого:
- Переиспользуйте буферы.
- Храните состояние в предсказуемых, плоских структурах.
- Используйте иммутабельные обновления только там, где нужно (а не везде!).

## [DoD](https://www.dataorienteddesign.com/dodbook/)
```js
const users = [
  { id: 1, name: "Alice", active: true, balance: 100 },
  { id: 2, name: "Bob", active: false, balance: 200 },
  // ...
];
```
```js
const users = {
  ids: [1, 2, ...],
  names: ["Alice", "Bob", ...],
  active: [true, false, ...],
  balances: [100, 200, ...]

```

## Ленивая загрузка (Lazy Loading)

**Суть**: загружать и инициализировать компоненты, данные или ресурсы **только по необходимости**.

- **Код**: динамические `import()` + `React.lazy` / `Suspense`
- **Изображения/видео**: `<img loading="lazy">`, `IntersectionObserver`
- **Данные**: загрузка по скроллу или при фокусе


## Оптимизация работы с DOM

**Суть**: минимизировать costful DOM-операции.

- **Batch-обновления**: React и другие фреймворки делают это автоматически.
- **DocumentFragment**: для массовой вставки узлов.
- **CSS вместо JS-анимаций**: `transform`, `opacity` → GPU-ускорение.
- **Избегать layout thrashing**: не читать и не писать layout-свойства в цикле (`offsetTop`, `clientWidth` и т.п.)

## Web Workers для тяжёлых вычислений

**Суть**: вынести CPU-интенсивные задачи (парсинг, фильтрация, расчёты) из основного потока.

- Примеры: обработка CSV, поиск по большому массиву, физика в 2D-игре.
- Можно комбинировать с **TypedArray** и **Transferable Objects** для эффективной передачи данных.

## Иммутабельность + структурное разделение (Structural Sharing)

**Суть**: использовать библиотеки вроде **Immer** или **Immutable.js**, чтобы:
- Избегать мутаций
- Быстро сравнивать состояния (`===` вместо deep-equal)
- Эффективно обновлять деревья (например, в редакторах)

## Оптимизация данных на уровне сети
- GraphQL: запрашивать только нужные поля → меньше данных → меньше памяти.
- JSON → [MessagePack](https://msgpack.org/) / [Protocol Buffers](https://protobuf.dev/): компактные форматы для больших объёмов.
- Pagination / Infinite scroll: не грузить всё сразу.

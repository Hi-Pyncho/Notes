### 1. **Базовый синтаксис**

```go
type Person struct {
    Name string
    Age  int
}
```

- Поля с заглавной буквы — экспортируемые (публичные).
- Поля со строчной — внутренние (приватные для пакета).

---

### 2. **Инициализация**

```go
p1 := Person{Name: "Alice", Age: 30}
p2 := &Person{Name: "Bob", Age: 25} // указатель на структуру
var p3 Person // нулевое значение (все поля — нулевые)
```

Go не имеет конструкторов, но часто используют **фабричные функции**:

```go
func NewPerson(name string, age int) *Person {
    return &Person{Name: name, Age: age}
}
```

Можно объявить кратко
```go
dog := struct {
    name   string
    isGood bool
}{
    "Rex",
    true,
}

```

### 3. **Встраивание (embedding)**

Go поддерживает композицию через встраивание:

```go
type Animal struct {
    Name string
}

type Dog struct {
    Animal // анонимное встраивание
    Breed  string
}

d := Dog{Animal: Animal{Name: "Rex"}, Breed: "Husky"}
fmt.Println(d.Name) // "Rex" — автоматически "поднято"
```

> ⚠️ Встраивание — это **не наследование**, а композиция. Но оно даёт удобный доступ к полям/методам встроенной структуры.

### 4. **Методы и интерфейсы**

Структуры могут иметь методы:

```go
func (p *Person) Greet() string {
    return "Hello, " + p.Name
}
```

Вызов методов на nil
Если метод вызывается на значении, равном nil, и этот метод не обращается к полям внутри объекта, то ошибка не возникает:

```go
type User struct {}

func (u *User) Info() {
  fmt.Println("info")
}

var u *User

u.Info()
```

Такое поведение разрешено в Go по дизайну. Аргумент u — это просто указатель на User, и метод может быть вызван даже на nil, если внутри метода нет обращения к данным. Это позволяет, например, реализовать "пустые" или "заглушки" (no-op реализации), где метод ничего не делает, но при этом вызывается безопасно.

Но если метод попытается обратиться к данным внутри структуры, произойдёт паника:

```go
type User struct {
    Name string
}

func (u *User) PrintName() {
    fmt.Println(u.Name)
}

func main() {
    var u *User
    u.PrintName() // panic: invalid memory address or nil pointer dereference
}

```

### 5. **Изменения в Go 1.22: циклы и переменные структур**

Одно из важнейших изменений в Go 1.22 — **новое поведение переменных цикла**:

```go
people := []Person{{Name: "A"}, {Name: "B"}}
var ptrs []*Person

for _, p := range people {
    ptrs = append(ptrs, &p) // ✅ В Go 1.22+ — безопасно!
}
```

- **До Go 1.22**: `p` — одна переменная, перезаписываемая на каждой итерации → все указатели указывали на последний элемент.
- **В Go 1.22+**: `p` **пересоздаётся на каждой итерации**, как если бы вы объявили `p := p` внутри тела цикла → каждый указатель уникален.

Это касается **любых типов**, включая структуры, примитивы и указатели.

> 💡 Это изменение делает код интуитивно правильным и устраняет одну из самых известных "ловушек" Go.

### 6. **Теги структур (struct tags)**

Используются для метаданных, особенно при сериализации:

```go
type User struct {
    ID   int    `json:"id"`
    Name string `json:"name,omitempty"`
}
```

Популярны в `json`, `xml`, `yaml`, `db`, `validate` и т.д.

---

### 7. **Выравнивание и память**

Go автоматически выравнивает поля структуры для эффективного доступа к памяти. Порядок полей влияет на размер структуры:

```go
type Bad struct {
    a bool   // 1 байт
    b int64  // 8 байт → требует выравнивания → 7 байт паддинга после a
    c bool   // 1 байт → ещё паддинг
} // итого: 24 байта

type Good struct {
    b int64
    a bool
    c bool
} // итого: 16 байт
```

Для оптимизации можно группировать поля по размеру.

---

### 8. **Сравнение структур**

Структуры **сравнимы**, если все их поля сравнимы:

```go
p1 := Person{Name: "Alice", Age: 30}
p2 := Person{Name: "Alice", Age: 30}
fmt.Println(p1 == p2) // true
```

Но если в структуре есть слайс, мапа или функция — она **нельзя сравнивать** (`==` вызовет ошибку компиляции).

### 9. **Анонимные структуры**

Иногда удобны для временных данных:

```go
data := struct {
  ID   int
  Desc string
}{
  ID: 1,
  Desc: "test",
}
```

Часто используются в тестах или при работе с JSON без создания именованного типа.

### Конструкторы
В Go нет синтаксиса конструкторов и деструкторов, но часто можно встретить аналог:
```go
func NewPerson(name, email string, dobYear, dobMonth, dobDay int) Person {
   return Person{
     Name:        name,
     Email:       email,
     dateOfBirth: time.Date(dobYear, time.Month(dobMonth), dobDay, 0, 0, 0, 0, time.UTC),
   }
 }
```
Вот некоторые правила, одобренные Go-сообществом:
- имя функции конструктора пишут с префиксом New;
- если конструктор производит валидацию аргументов, функция должна возвращать ошибку последним аргументом.
```go
func NewPerson(name, email string, dobYear, dobMonth, dobDay int) (Person, error) {}
```

### Тэги
У каждого поля структуры может быть набор аннотаций, которые называются тегами (tags):
```go
type GetUserRequest struct {
  UserId string `json:"user_id" yaml: "user_id" format:"uuid" example:"2e263a90-b74b-11eb-8529-0242ac130003"`
  IsDeleted *bool `json:"is_deleted,omitempty" yaml:"is_deleted"`
}
```
Теги не влияют на представление или работу с данными напрямую, но могут использоваться пакетами для получения дополнительной информации о конкретном поле.
Набор тегов с их значениями можно представить как набор ключей и значений, где ключи разделяются пробелами, а значения ключей — запятой.

В примере выше встречаются следующие теги:
- json — используется пакетом encoding/json для сериализации/десерилизации структур в JSON;
- yaml — похож на json, но используется внешними библиотеками для работы с форматом YAML;
- format и example — могут быть как подсказкой для разработчика, так и аннотацией для генерации Swagger-описания (к примеру, библиотекой swag).

Применяемые аннотации чаще всего зависят от используемой библиотеки. Возможные ключи и значения стоит искать в документации пакета (в худшем случае — в коде).

```go
type Person struct {
  Name        string `json:"Имя"`
  Email       string `json:"Почта"`
  DateOfBirth time.Time `json:"-"` // - означает, что это поле не будет сериализовано
}

func main() {
  p := Person{
    Name: "tisha",
    Email: "sfdf@jfdjf.com",
    DateOfBirth: time.Now(),
  }

  res, err := json.Marshal(p)

  if (err != nil) {
    log.Fatalln("unable marshal to json")
  }

	fmt.Println(string(res)) // {"Имя":"tisha","Почта":"sfdf@jfdjf.com"}
}
```

## 🗺️ Roadmap изучения Go

### **Уровень 0: Подготовка**
- Установка Go: [golang.org/dl](https://golang.org/dl)
- Настройка среды: VS Code / GoLand + расширения
- Понимание базовой командной строки: `go run`, `go build`, `go mod init`

---

### **Уровень 1: Основы языка**
> Цель: писать простые программы на Go

1. **Синтаксис и структура программы**
   - Пакеты (`package main`, `import`)
   - Функция `main()`
   - Комментарии

2. **Переменные и типы данных**
   - `var`, `:=`, нулевые значения
   - Базовые типы: `int`, `float64`, `bool`, `string`
   - Константы (`const`)

3. **Управляющие конструкции**
   - `if` / `else`
   - `for` (единственный цикл в Go!)
   - `switch`

4. **Функции**
   - Объявление, параметры, возврат значений
   - Множественный возврат (`func f() (int, error)`)
   - Анонимные функции

5. **Встроенные структуры данных**
   - **Массивы** (`[3]int`)
   - **Срезы** (`[]int`) — создание, длина/ёмкость, `append`, срезание
   - **Мапы** (`map[string]int`) — создание, проверка наличия ключа
   - **Строки** и работа с `rune`/`byte`

---

### **Уровень 2: Продвинутые основы**
> Цель: писать идиоматичный, чистый Go-код

6. **Указатели**
   - `&` и `*`
   - Передача по ссылке
   - Нулевое значение — `nil`

7. **Структуры и методы**
   - `struct`
   - Методы с получателями (value vs pointer receivers)
   - Конструкторы (например, `NewUser()`)

8. **Интерфейсы**
   - Неявная реализация интерфейсов
   - Пустой интерфейс `interface{}` → в Go 1.18+ лучше `any`
   - Полиморфизм через интерфейсы

9. **Обработка ошибок**
   - Идиома: `if err != nil`
   - Создание кастомных ошибок (`errors.New`, `fmt.Errorf`)
   - Оборачивание ошибок (`%w`)

10. **Паника и восстановление (`panic` / `recover`)**
    - Использовать редко! Только в исключительных случаях.

---

### **Уровень 3: Параллелизм и системное программирование**
> Цель: писать конкурентные и эффективные приложения

11. **Горутины (`goroutines`)**
    - `go func()`
    - Лёгкие потоки выполнения

12. **Каналы (`channels`)**
    - Буферизованные и небуферизованные
    - `ch := make(chan int)`
    - `select` для работы с несколькими каналами

13. **Примитивы синхронизации**
    - `sync.WaitGroup`
    - `sync.Mutex`, `sync.RWMutex`
    - `sync.Once`, `sync.Map` (осторожно!)

14. **Context**
    - Отмена операций (`context.WithCancel`)
    - Таймауты (`context.WithTimeout`)
    - Передача значений (`context.WithValue` — осторожно!)

---

### **Уровень 4: Стандартная библиотека и инструменты**
> Цель: использовать мощь стандартной библиотеки

15. **Работа с файлами и I/O**
    - `os`, `io`, `bufio`

16. **JSON и сериализация**
    - `json.Marshal` / `json.Unmarshal`
    - Теги структур: `` `json:"name"` ``

17. **HTTP-сервер и клиент**
    - `net/http`: создание REST API
    - Middleware, маршрутизация (можно начать с `net/http`, потом — Gin/Fiber)

18. **Тестирование**
    - `_test.go` файлы
    - `go test`
    - Таблицы тестов, моки, бенчмарки

19. **Модули и зависимости**
    - `go.mod`, `go.sum`
    - `go get`, `go tidy`

20. **Инструменты разработчика**
    - `go fmt`, `go vet`, `golint` (или `golangci-lint`)
    - `go doc`, `go run`, `go build`

---

### **Уровень 5: Продвинутые темы и практика**
> Цель: писать production-ready приложения

21. **Проектирование API**
    - REST, JSON-API
    - Валидация входных данных
    - Обработка ошибок на уровне HTTP

22. **Работа с базами данных**
    - `database/sql` + драйвер (например, `pq` для PostgreSQL)
    - ORM (GORM) — опционально

23. **Логирование**
    - `log` → лучше `slog` (Go 1.21+) или `zap`/`logrus`

24. **Конфигурация**
    - Переменные окружения (`os.Getenv`)
    - Файлы конфигурации (Viper)

25. **Docker и развёртывание**
    - Минимальный Dockerfile для Go
    - Мультистадийная сборка

26. **Профилирование и оптимизация**
    - `pprof`
    - Анализ памяти и CPU

---

### **Уровень 6: Экосистема и архитектура**
> Цель: строить масштабируемые системы

27. **Фреймворки и библиотеки**
    - Web: Gin, Echo, Fiber
    - CLI: Cobra
    - gRPC, Protobuf

28. **Паттерны проектирования в Go**
    - Dependency Injection (вручную или через Wire/Dig)
    - Clean Architecture / Hexagonal Architecture
    - Repository pattern

29. **Тестирование: моки, интеграционные тесты**
    - `testify/mock`
    - Запуск тестов с БД в Docker

30. **CI/CD**
    - GitHub Actions / GitLab CI для Go-проектов

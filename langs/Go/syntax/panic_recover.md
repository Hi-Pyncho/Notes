`panic` и `recover` — это встроенные функции в языке Go (Golang), которые управляют поведением программы при возникновении неожиданных или критических ошибок.

### `panic`

- `panic` — это встроенная функция, которая немедленно прекращает выполнение текущей функции.
- После вызова `panic`, все отложенные (`defer`) функции в текущей горутине выполняются в обратном порядке (LIFO), как обычно.
- После выполнения всех `defer`-функций, программа аварийно завершается (crash).
- Обычно `panic` вызывается, когда происходит что-то неожиданное, например:
  - Попытка обращения к элементу слайса за его пределами.
  - Вызов `panic` вручную (например, если программист решил, что ситуация непоправима).
- Пример:
  ```go
  func main() {
      fmt.Println("before panic")
      panic("something went wrong")
      fmt.Println("after panic") // Это не будет выполнено
  }
  ```

### `recover`

- `recover` — это встроенная функция, которая позволяет восстановить контроль над паникующей горутиной.
- `recover` может использоваться **только** внутри `defer`-функции.
- Если `recover` вызывается во время паники, он останавливает панику и возвращает значение, которое было передано в `panic`.
- Если `recover` вызывается, когда **нет** активной паники, он возвращает `nil`.
- Это позволяет "перехватить" панику и, например, корректно завершить работу или залогировать ошибку, вместо аварийного завершения программы.

### Пример использования `recover`

```go
func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Recovered from panic:", r)
        }
    }()

    fmt.Println("Before panic")
    panic("something went wrong")
    fmt.Println("After panic (this will not be printed)")
}
```

### Когда использовать `panic` и `recover`?

- **Не злоупотребляйте** `panic` и `recover`.
- В Go предпочтительно использовать возвращаемые ошибки (`error`) для обработки ожидаемых ошибочных ситуаций.
- `panic` и `recover` предназначены для **исключительных ситуаций**, когда продолжать выполнение программы небезопасно или невозможно.
- `recover` полезен, например, в библиотечном коде, чтобы избежать аварийного завершения всей программы из-за ошибки в пользовательской функции.

### Резюме

- `panic` — останавливает выполнение функции и вызывает `defer`-функции, а затем аварийно завершает программу.
- `recover` — позволяет перехватить `panic` и восстановить нормальное выполнение, но работает **только** внутри `defer`-функции.
- Используйте `panic`/`recover` с осторожностью, в основном для внутренних ошибок или фатальных ситуаций.
